# Настройка части 1С

Все имена объектов и реквизитов ниже должны совпадать буквально: модуль HTTP-сервиса
обращается к ним по имени.

## 1. Подсистема

Создайте подсистему `РегистрацияЗаявок` с синонимом «Регистрация заявок».

## 2. Перечисления

### `ПриоритетыЗаявок`

Значения:

- `Низкий`;
- `Обычный`;
- `Высокий`.

### `СтатусыЗаявок`

Значения:

- `Новая`;
- `ВРаботе`;
- `Выполнена`;
- `Отклонена`;
- `Отменена`.

## 3. Справочники

### `КатегорииЗаявок`

Используются стандартные реквизиты `Код` и `Наименование`. Длина наименования — 100.

Создайте минимум четыре элемента:

- Техническая проблема;
- Доступ и учётные записи;
- Установка программ;
- Другое.

### `ПользователиТелеграм`

Длина наименования — 200. Реквизиты:

| Имя | Тип |
| --- | --- |
| `TelegramID` | Число(20, 0), неотрицательное |
| `Username` | Строка(100) |
| `ПолноеИмя` | Строка(200) |

Для реквизита `TelegramID` включите индексирование. Наименование будет автоматически
заполняться полным именем пользователя.

## 4. Документ `Заявка`

Автонумерация включена, длина номера — 9. Реквизиты:

| Имя | Тип |
| --- | --- |
| `ПользовательТелеграм` | СправочникСсылка.ПользователиТелеграм |
| `Категория` | СправочникСсылка.КатегорииЗаявок |
| `Тема` | Строка(120) |
| `Описание` | Строка(2000) |
| `Приоритет` | ПеречислениеСсылка.ПриоритетыЗаявок |
| `Статус` | ПеречислениеСсылка.СтатусыЗаявок |

Проведение документа не требуется. Создайте формы документа и списка автоматически.

## 5. Константа

Создайте константу `ТокенHTTPСервиса`, тип `Строка(200)`. Это общий секрет между
ботом и 1С. Не используйте в качестве него токен Telegram. Бот передаёт секрет
в заголовке `X-API-Key`: стандартный заголовок `Authorization: Bearer` использовать
нельзя, потому что его перехватывает механизм аутентификации платформы 1С.

## 6. HTTP-сервис

Создайте HTTP-сервис:

- имя: `IssueAPI`;
- корневой URL: `issue-api`;
- время жизни сеанса: `20`;
- повторное использование сеансов: «Не использовать».

Добавьте шаблоны URL и методы:

| Шаблон URL | HTTP-метод | Имя обработчика |
| --- | --- | --- |
| `/v1/categories` | GET | `CategoriesGET` |
| `/v1/issues` | GET | `IssuesGET` |
| `/v1/issues` | POST | `IssuesPOST` |
| `/v1/issues/{id}` | GET | `IssueGET` |
| `/v1/issues/{id}/cancel` | POST | `IssueCancelPOST` |

Скопируйте содержимое файла `IssueAPI_Module.bsl` в модуль HTTP-сервиса.

## 7. Начальное заполнение

Запустите базу в режиме 1С:Предприятие:

1. заполните справочник категорий;
2. задайте случайное значение константы `ТокенHTTPСервиса`;
3. то же значение укажите в `.env` бота как `ONEC_API_TOKEN`.

## 8. Публикация

HTTP-сервис должен быть опубликован на веб-сервере. После публикации полный адрес
будет иметь вид:

```text
http://localhost/<имя-публикации>/hs/issue-api/v1
```

Его нужно записать в `.env`:

```dotenv
BOT_MODE=onec
ONEC_BASE_URL=http://localhost/<имя-публикации>/hs/issue-api/v1
ONEC_API_TOKEN=<общий секрет>
```
