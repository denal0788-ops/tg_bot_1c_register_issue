# Telegram-бот регистрации заявок в 1С

Telegram-бот принимает обращения пользователей и сохраняет их в информационной базе
1С через HTTP-сервис. Пользователь может создать заявку, посмотреть её состояние и
отменить заявку, пока она не принята в работу.

## Возможности

- пошаговое создание заявки в Telegram;
- получение категорий из справочника 1С;
- выбор категории и приоритета кнопками;
- подтверждение заявки перед отправкой;
- автоматическая регистрация пользователя Telegram в 1С;
- просмотр списка и карточки собственных заявок;
- получение актуального статуса из 1С;
- отмена заявки со статусом «Новая»;
- mock-режим для запуска без 1С;
- авторизация запросов к 1С по заголовку `X-API-Key`.

## Архитектура

```text
Telegram → Python / aiogram → HTTP JSON API → 1С:Предприятие
```

Python-приложение отвечает за Telegram-интерфейс и состояние диалога. В 1С хранятся
пользователи, категории и документы заявок. Связь выполняется через HTTP-сервис
`IssueAPI`.

## Требования

### Для Telegram-бота

- Windows 10 или 11;
- Python 3.12 или новее;
- токен Telegram-бота от [@BotFather](https://t.me/BotFather).

### Для 1С

- 1С:Предприятие 8.3.27 или новее;
- компонент платформы «Модули расширения веб-сервера»;
- Microsoft IIS;
- расширения ISAPI и фильтры ISAPI в компонентах IIS.

Если установлена 32-разрядная платформа 1С, для используемого пула приложений IIS
нужно включить параметр «Разрешены 32-разрядные приложения».

## Установка Python-приложения

Откройте PowerShell в корне репозитория и создайте виртуальное окружение:

```powershell
python -m venv .venv
```

Установите проект и зависимости:

```powershell
.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

Создайте локальный файл настроек:

```powershell
Copy-Item .env.example .env
```

Файл `.env` исключён из Git. Не добавляйте в репозиторий токены и другие секреты.

## Запуск без 1С

Укажите в `.env` токен Telegram и mock-режим:

```dotenv
BOT_TOKEN=<токен от BotFather>
BOT_MODE=mock
```

Запустите приложение:

```powershell
.venv\Scripts\python.exe -m tg_bot
```

В mock-режиме заявки хранятся в памяти и удаляются после остановки процесса.

## Настройка 1С

Полный список объектов, реквизитов и обработчиков приведён в
[`onec/README.md`](onec/README.md).

Краткий порядок настройки:

1. Создать перечисления `ПриоритетыЗаявок` и `СтатусыЗаявок`.
2. Создать справочники `КатегорииЗаявок` и `ПользователиТелеграм`.
3. Создать документ `Заявка`.
4. Создать константу `ТокенHTTPСервиса`.
5. Создать HTTP-сервис `IssueAPI` с корневым URL `issue-api`.
6. Добавить шаблоны URL и обработчики согласно `onec/README.md`.
7. Скопировать `onec/IssueAPI_Module.bsl` в модуль HTTP-сервиса.
8. Обновить конфигурацию базы данных.
9. Заполнить категории и значение константы в режиме 1С:Предприятие.

Значение `ТокенHTTPСервиса` должно быть отдельным секретом. Токен Telegram для этого
не используется.

## Подготовка IIS

В компонентах Windows включите:

- «Службы IIS»;
- «Консоль управления IIS»;
- «Расширения ISAPI»;
- «Фильтры ISAPI»;
- «Статическое содержимое»;
- «Документ по умолчанию»;
- «Ошибки HTTP».

Для файловой базы предоставьте права на чтение и изменение каталога базы следующим
учётным записям:

- `IUSR`;
- `IIS_IUSRS`;
- при необходимости `IIS AppPool\DefaultAppPool`.

Права должны распространяться на каталог базы и файл `1Cv8.1CD`.

## Публикация HTTP-сервиса

Запустите конфигуратор от имени администратора и откройте:

```text
Администрирование → Публикация на веб-сервере
```

Рекомендуемые параметры локальной публикации:

```text
Имя публикации: tg_project
Веб-сервер: Internet Information Services
Каталог: C:\inetpub\wwwroot\tg_project
```

На вкладке «HTTP-сервисы» включите публикацию `IssueAPI`. Публикация веб-клиента,
OData, системы аналитики и Web-сервисов для работы бота не требуется.

Базовый адрес опубликованного API:

```text
http://localhost/tg_project/hs/issue-api/v1
```

После изменения BSL-кода обновите конфигурацию базы данных и перезапустите пул
приложений IIS.

## Подключение бота к 1С

Заполните `.env`:

```dotenv
BOT_TOKEN=<токен от BotFather>
BOT_MODE=onec
ONEC_BASE_URL=http://localhost/tg_project/hs/issue-api/v1
ONEC_API_TOKEN=<значение константы ТокенHTTPСервиса>
ONEC_TIMEOUT_SECONDS=10
LOG_LEVEL=INFO
```

Запустите бота:

```powershell
.venv\Scripts\python.exe -m tg_bot
```

## Проверка API

Проверить получение категорий можно из PowerShell:

```powershell
$config = Get-Content .env |
    Where-Object { $_ -match "^[A-Z_]+=" } |
    ConvertFrom-StringData

curl.exe -i `
    -H "X-API-Key: $($config.ONEC_API_TOKEN)" `
    "$($config.ONEC_BASE_URL)/categories"
```

Исправный сервис возвращает `HTTP/1.1 200 OK` и массив `items` с категориями из 1С.

## HTTP API

| Метод | Адрес | Назначение |
| --- | --- | --- |
| `GET` | `/categories` | Получить категории |
| `POST` | `/issues` | Создать заявку |
| `GET` | `/issues` | Получить заявки пользователя |
| `GET` | `/issues/{id}` | Получить карточку заявки |
| `POST` | `/issues/{id}/cancel` | Отменить новую заявку |

Полный формат запросов и ответов описан в
[`docs/1c_http_api.md`](docs/1c_http_api.md).

## Возможные ошибки

- `404 Not Found` — проверьте имя публикации и `ONEC_BASE_URL`.
- `401 Unauthorized` — не совпадают `ONEC_API_TOKEN` и `ТокенHTTPСервиса`.
- `500.21 IsapiModule` — в IIS не включены расширения ISAPI.
- Ошибка доступа к каталогу базы — учётным записям IIS не выданы права на базу.
- Изменения BSL не применились — обновите конфигурацию базы и перезапустите пул IIS.

## Безопасность

- не публикуйте `.env`;
- не передавайте токен Telegram в 1С;
- используйте отдельное значение `ONEC_API_TOKEN`;
- перед публикацией репозитория проверяйте `git status` на наличие секретов.
